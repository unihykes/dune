# Cursor Skill Usage: `canvas`

## 一句话怎么用

当结果是“结构化分析交付物”时，直接说：  
**“请用 canvas 产出，不要纯 markdown 表格。”**

---

## 什么时候应该主动用 canvas

适合：

- 数据分析结果要展示（统计、对比、明细表）
- 安全审计、架构评审、账单分析这类报告
- 需要“可浏览的页面感”，而不是长段文本

不适合：

- 只是改代码、修 bug、提 PR
- 用户明确要求去别的系统里操作
- 一两段短说明就能说清的问题

---

## 推荐使用步骤（用户视角）

1. **明确交付物**
   - “请做一个可视化分析画布，包含概览+明细+结论。”
2. **给结构要求**
   - “上方放 KPI，中间表格，底部风险与建议。”
3. **给内容边界**
   - “只展示这次分析相关数据，不要扩展到其它模块。”
4. **要可读性检查**
   - “请确认重点能一眼看出，避免花哨样式。”

---

## 可直接复用的提问模板

- `请用 canvas 输出这次接口错误分析，包含总览、按服务拆分、Top 10 明细。`
- `如果你准备写 markdown 表格，改为 canvas 展示。`
- `做成可汇报样式：结论在前，证据在后。`
- `请给一个简洁版本，避免渐变、emoji、阴影。`

---

## 你应当看到的“正确产物”

- 输出为独立 `.canvas.tsx` 画布文件
- 结构有层次（概览 -> 细节 -> 结论）
- 信息密度高但可读，不是“卡片堆砌”
- 样式克制，强调信息而非装饰

---

## 常见失败点

- 没有说“用 canvas”，结果返回普通文字
- 需求只给“做个报告”，没给展示结构
- 强调美观大于信息，导致可读性变差
- 本应短答也强行上 canvas，使用成本过高
