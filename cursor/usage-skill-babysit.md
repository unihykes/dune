# Cursor Skill Usage: `babysit`

## Skill 目的

`babysit` 用于把一个 PR 持续维护到“可合并状态”。  
它不是一次性动作，而是一个循环流程：看评论 -> 修问题 -> 看 CI -> 再修，直到可合并。

---

## 典型适用场景

- PR 已开出，但评论和 CI 反复出现新问题
- 需要持续跟进 Bugbot/同事反馈并快速收敛
- 分支与基线分支有冲突，需要安全解决并继续验证

---

## 核心工作流

1. 检查 PR 当前状态（mergeability、CI、最新评论）
2. 逐条处理评论（包括 Bugbot）
3. 有冲突时与基线同步并谨慎解决
4. 修复 CI（小步、聚焦、可验证）
5. 推送后继续观察，直到“可合并 + CI 全绿 + 评论已处理”

---

## 使用要点

- 只修你认同的问题；不认同时要解释原因
- 处理冲突时，如果双方意图不清晰，应停下来确认，不要猜
- 修 CI 要做小范围变更，避免引入额外风险
- 目标是“merge-ready”，不是无边界重构

---

## 学习建议

- 把 `babysit` 当作“PR 运维能力”训练
- 每轮都输出简短状态：剩余评论数、CI 状态、阻塞项
- 与 `review`、`summarize` 配合：先审查，再维护，最后总结

---

## 常见误区

- 一次改太多，导致定位回归困难
- 冲突直接机械接受一方，忽略语义差异
- 只看 CI，不回评论（或只回评论，不修 CI）
