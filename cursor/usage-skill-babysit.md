# Cursor Skill Usage: `babysit`

## 一句话怎么用

当你希望 Cursor 持续“盯 PR 到可合并”时，在需求里明确说：  
**“用 babysit 把这个 PR 跟进到 merge-ready。”**

---

## 你应该提供的输入

至少给 3 类信息，效果最好：

- PR 入口：PR 链接，或分支名 + 仓库
- 目标标准：例如“CI 全绿 + 所有评论已处理”
- 边界约束：例如“不要大重构，只做必要修复”

---

## 推荐使用步骤（照着发即可）

1. **启动任务**
   - “请用 `babysit` 跟进这个 PR，直到可合并。”
2. **先要基线报告**
   - “先给我当前状态：评论数、冲突、CI 项、主要阻塞。”
3. **进入循环处理**
   - “按严重度先修 blocker，再处理普通评论。”
4. **每轮回报**
   - “每一轮告诉我：已处理项、剩余项、下一步。”
5. **收尾确认**
   - “确认现在是否满足 merge-ready，若否请列最后阻塞。”

---

## 可直接复用的提问模板

- `请用 babysit 跟进 PR #123，目标是今天合并。`
- `先 triage 所有评论（含 Bugbot），只修你认同的问题。`
- `冲突只在语义明确时解决，不明确请先停下来问我。`
- `CI 只做小范围修复，每次改动后汇报风险。`
- `最后输出“可合并检查清单”再结束。`

---

## 什么时候算“用对了”

你应该看到这种结果：

- 评论被分组处理（已修复 / 不认同 / 待确认）
- CI 失败项逐步减少，并有明确修复说明
- 冲突处理有依据，不是机械选一边
- 最终输出明确结论：是否 merge-ready

---

## 常见失败点（学习时重点避开）

- 指令太笼统，只说“看下 PR”
- 不给边界，导致无关改动扩大范围
- 不要求轮次回报，中途状态不透明
- 不定义“完成标准”，任务容易拖长
