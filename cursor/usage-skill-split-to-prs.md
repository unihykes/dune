# Cursor Skill Usage: `split-to-prs`

## 一句话怎么用

当你改动太大、难 review 时，直接说：  
**“请用 split-to-prs 把当前改动拆成小 PR 方案，先给计划等我确认。”**

---

## 你应该先给的信息

- 当前分支或 PR 背景
- 你希望拆成几部分（可选）
- 依赖关系（哪些必须先合）
- 是否允许创建新分支与推送

---

## 推荐使用步骤

1. 让 Cursor 先“盘点现状 + 切片建议”
2. 明确要求“先计划，不执行”
3. 你确认后，再让它逐片执行
4. 每片执行后回报 PR 标题与范围

---

## 可直接复用的提问模板

- `请用 split-to-prs 分析当前工作，先给拆分方案，不要直接提交。`
- `优先拆成独立 PR，只有强依赖时才做堆叠 PR。`
- `每个 PR 用一句话说明范围和风险。`
- `执行前先做可恢复快照，并告诉我快照信息。`

---

## 成功判断标准

- 每个 PR 主题单一，review 负担明显下降
- 依赖关系清晰，不出现“后面的 PR 依赖前面未合并细节”
- 拆分过程可回退，有备份点
- 未经确认不会擅自推送或开 PR

---

## 常见失败点

- 只按目录拆，不按业务边界拆
- 跳过确认阶段直接执行
- 拆分前没备份，回退困难
- 每个 PR 改动仍过大，失去拆分意义
