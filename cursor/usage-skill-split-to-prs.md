# Cursor Skill Usage: `split-to-prs`

## Skill 目的

`split-to-prs` 用于把“一个大改动堆”拆成多个可评审的小 PR，提升可读性、可回归性和合并效率。

---

## 适用场景

- 一个分支混了多类改动（功能、重构、文档）
- PR 过大，review 成本过高
- 需要按依赖关系分批提交

---

## 硬性原则（非常重要）

- 未获用户确认前，不要直接建分支/提交/推送/开 PR
- 禁止破坏性 git 操作（如 `reset --hard`、`clean -fdx` 等）
- 拆分前先做可恢复快照
- 只按文件或 hunk 精准暂存，不用 `git add .`

---

## 推荐流程

1. 盘点当前变更（含已提交与未提交）
2. 归纳“自然切片”（按功能边界而非文件数量）
3. 给出拆分方案并等待确认
4. 按确认方案执行拆分与提交流程
5. 回报结果（PR 列表、遗留项、风险点）

---

## 拆分策略建议

- 默认优先“相互独立的并行 PR”
- 只有真实依赖时才做“堆叠 PR”
- 每个 PR 保持单一主题，可一句话讲清楚

---

## 常见误区

- 按目录硬拆，忽略业务依赖
- 在未备份前就移动改动
- 追求数量平均而不是语义清晰
