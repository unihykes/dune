# Cursor Command Usage: `read-branch`

## 一句话怎么用

想快速读懂一个分支时说：  
**“请用 `read-branch` 解读当前分支相对 `main` 的改动。”**

---

## 使用前建议提供的信息

- 基线分支（通常 `main`）
- 关注重点（接口变化、风险、测试缺口）
- 输出形式（按模块、按优先级、按文件）

---

## 推荐使用步骤

1. 切到目标分支执行 `read-branch`
2. 先拿改动总览和主题归纳
3. 再要“重点文件 + 高风险点”
4. 最后要“建议 review 顺序”

---

## 可直接复用的提问模板

- `请用 read-branch 对比 main，按模块分组解读改动。`
- `重点告诉我行为变化，不要只列文件名。`
- `请列出潜在回归风险和测试空白。`
- `给我一个 review 顺序：先看哪些文件最值。`

---

## 成功判断标准

- 你能一句话讲清这个分支在做什么
- 知道哪些改动“影响行为”而非仅重排代码
- 明确高风险区域和优先检查点
- 形成可执行的 review 路线

---

## 常见失败点

- 只看文件数量，不看语义变化
- 不指定基线分支，结论容易偏差
- 不追问“为什么改”，只看“改了啥”
- 把 read-branch 结果当最终结论，不做验证
