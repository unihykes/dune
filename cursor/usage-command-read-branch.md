# Cursor Command Usage: `read-branch`

## 命令目的

`read-branch` 的核心用途是：帮助你快速理解“当前分支相对基线分支（如 main）做了什么改动”。  
它更偏向“分支级别阅读”，而不是单文件解释。

简单说，它帮助你回答：  
“这个分支到底改了哪些点、为什么改、风险在哪、我该怎么 review？”

---

## 适用场景

- 接手同事分支，想快速了解改动范围
- 开始 code review 前，先建立整体认知
- 改动很多文件时，先拿到结构化导读
- 准备写 PR 描述或变更说明

---

## 基本用法

常见使用方式：

1. 切到目标分支
2. 执行 `read-branch`
3. 让 Cursor 输出“改动概览 + 重点文件 + 潜在风险”

你还可以补充限定语，例如：

- “按模块分组解读”
- “重点看接口行为变化”
- “只看可能影响线上稳定性的部分”

---

## 典型输出结构

高质量的 `read-branch` 结果通常会包含：

- 分支改动的主题和目标
- 主要文件/目录变更分布
- 关键逻辑变化摘要
- 兼容性影响（接口、配置、数据结构）
- 测试覆盖情况和缺口
- 建议优先 review 的文件顺序

---

## 实战建议

- 先让 `read-branch` 给总览，再逐个打开重点文件验证
- 对“高风险结论”要求给出具体文件依据
- 结合 `review` 命令做第二轮深入检查

推荐流程：

`read-branch`（建立全局认知） -> `review`（深入找问题） -> 手工验证关键点

---

## 常见误区

- **误区 1：** 只看“改了哪些文件”不看“行为变化”  
  重点应放在行为和影响面，不是改动行数。

- **误区 2：** 忽略隐式变更  
  比如默认值、配置、异常分支，这些经常在 diff 中不显眼但影响大。

- **误区 3：** 把它当作最终审查结论  
  它是阅读加速器，不是完整测试替代品。
